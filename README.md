# CHIDA — چیدا

چیدا همکار هوشمند و منبع‌دار بازار ساخت ایران است: یک فضای گفت‌وگومحور که نیاز سازنده را به کار، سند، تصمیم و شیء ماندگار تبدیل می‌کند و جریان خرید را تا مقایسه، مذاکره و تبادل رضایتمندانهٔ اطلاعات تماس پیش می‌برد.

منبع حقیقت محصول [سند مادر تعریف محصول](./CHIDA-Product-Definition-FA.md) است. فهرست قابلیت‌های بعدی سازنده در [بک‌لاگ سازنده](./BUILDER-FEATURE-BACKLOG-FA.md) نگه‌داری می‌شود. تجربه‌های واقعی ساخت، شکاف‌های سند مادر و تصمیم‌های مرحله‌ای در [دفتر یادگیری محصول](./CHIDA-PRODUCT-LEARNINGS-FA.md) ثبت می‌شوند؛ این دفتر تا زمان انتقال صریح تصمیم‌ها به سند مادر، مرجع تعریف محصول نیست.

## وضعیت فعلی

پروتوتایپ فعلی یک اپ فارسی RTL، Mobile-first و Dark-only است. موبایل و دسکتاپ دو حالت طراحی مستقل‌اند؛ دامنهٔ فعال فعلاً فقط موبایل با هدف بصری `390 × 844` است و طراحی دسکتاپ بعداً جداگانه انجام می‌شود. مسیرهای فعلی:

- انتخاب نقش با قاعدهٔ «یک حساب، یک نقش»؛
- ورود سازنده با کد دعوت، شمارهٔ موبایل و OTP ازپیش‌پرشده؛
- خانهٔ چت‌محور با پروژهٔ فعال، Composer، حالت پاسخ، فایل، صدا، ابزارها و Drawer راست؛
- فضای تمام‌صفحهٔ پروژه با شناسنامهٔ تدریجی، کتابخانهٔ فایل‌های پروژه‌محور، گالری تصاویر و حافظهٔ دستیِ شفاف؛ فایل‌های غیرتصویری فقط با metadata، عکس‌ها فقط در همان مرورگر و هر حافظه فقط در پروژهٔ مالک خودش نگه‌داری می‌شوند؛
- جست‌وجوی محلی و قطعی در حافظه و شناسنامهٔ فایل‌های پروژهٔ فعال، همراه با منشأ، تاریخ، نسخه، محدوده و بازکردن رکورد اصلی؛
- Build برای تعریف، پیش‌نمایش دقیق و فعال‌سازی محلی یک نمای امن و فقط‌خواندنی در همان پروژه؛
- Brief با برنامهٔ روزانه یا هفتگی و خلاصهٔ ماندگار در مرورگر.

Project/ProjectProfile و انتخاب پروژهٔ فعال در foundation اتمیک و نسخه‌دار v3 نگه‌داری می‌شوند و Identity/Policy fixture دقیق، migration fail-close و رقابت چندتب برای آن آزموده شده‌اند. Task دستی نیز canonical envelope نسخهٔ ۲ با history، fingerprint، migration و mutation هم‌زمان امن دارد و writerهای Request/recovery و مرز مستقیم Request↔Approval stale overwrite را رد می‌کنند. Build، Brief، OTP، چت، ثبت فایل، گالری، حافظه و بازیابی فعلی در این مرحله محلی‌اند و هیچ اقدام بیرونی، آپلود ابری، همگام‌سازی یا نصب واقعی انجام نمی‌دهند. Build فقط از کاتالوگ بسته یک `BuiltArtifact` declarative و project-scoped می‌سازد؛ پلاگین/اسکیل واقعی یا اجرای کد نیست. حافظه فقط با ثبت مستقیم کاربر ساخته می‌شود؛ پیام‌ها و فایل‌ها خودکار حافظه نمی‌شوند و ترجیح استفاده در زمینه هنوز به مدل وصل نیست. جست‌وجوی فعلی عنوان و متن حافظهٔ دستی و فقط metadata فایل‌های همان پروژه را تطبیق می‌دهد؛ محتوای فایل، OCR، وب، بازار، پاسخ AI و استناد منبع‌دار تا اتصال منابع واقعی غیرفعال‌اند.

## اجرای محلی

```bash
cd prototype
npm ci --prefer-offline --no-audit --no-fund
npm run dev
```

سپس `http://127.0.0.1:5173/` را باز کنید.

مقادیر آمادهٔ ورود:

- کد دعوت: `CHD-4K9P`
- موبایل: `09123456789`
- OTP: `123456`

## تست و ساخت

```bash
cd prototype
npm run test:app -- --grep "نام regression مرتبط"
npm run check:runtime
npm run build
```

این مسیر توسعهٔ روزمره است: regression مرتبط، integrity runtime و یک build پس از جمع‌شدن بستهٔ بازخورد. `npm run gate:release` فقط یک بار روی candidate منجمدِ انتشار صریح یا پایان یک برش پرریسک معماری اجرا می‌شود؛ build/integrity/TypeScript، همهٔ آزمون‌های Playwright، Sites و whitespace را اجرا و fingerprint منبع و `dist` را خارج از working tree ثبت می‌کند. پس از مجوز جداگانهٔ انتشار، همان candidate باید commit شود و `npm run gate:publish` پیش از تنها push اجرا شود؛ تغییر source، mode/symlink، history غیرمستقیم یا بستهٔ build گیت را باطل می‌کند.

خروجی Cloudflare Pages در `prototype/dist/client` و بستهٔ ChatGPT Sites در `prototype/dist` آماده می‌شود. برای توسعهٔ متمرکز، `npm run test:app` فقط suite برنامه و `npm run test:runtime` فقط هشت آزمون runtime را اجرا می‌کنند.

## مرز محصول

چیدا بازار عمومی، تضمین‌کنندهٔ معامله، مجری پرداخت/قرارداد/حمل، ERP، نرم‌افزار حسابداری رسمی یا عامل خودمختار بدون تأیید انسان نیست. خروجی حساس باید قابل‌ردیابی، منبع‌دار، نسخه‌دار و قابل‌اصلاح باشد.
