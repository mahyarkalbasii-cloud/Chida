# پروتوتایپ واکنش‌گرای CHIDA

پروتوتایپ واقعی، کلیک‌پذیر و تمام‌صفحهٔ مسیر ورود سازنده تا خانهٔ چت‌محور چیدا. هدف فعلی فقط نمای موبایل `390 × 844` است و قاب نمایشی موبایل جزو محصول نیست. موبایل و دسکتاپ دو حالت طراحی مستقل‌اند؛ نمایش ستون موبایل در viewport عریض، طراحی دسکتاپ محسوب نمی‌شود و نمای دسکتاپ بعداً جداگانه ساخته خواهد شد.

## فلو فعال

1. انتخاب نقش؛ هر دو نقش قابل انتخاب‌اند، اما تأمین‌کننده فعلاً پیام «به‌زودی» می‌بیند.
2. کد دعوت سازنده: `CHD-4K9P`
3. موبایل نمونه: `09123456789`
4. OTP نمونه: `123456`
5. ساخت پروژه با نام، محدودهٔ تهران و مرحلهٔ ساخت و ورود به خانهٔ چت.
6. بازکردن فضای پروژه، تکمیل شناسنامه، ثبت محلی metadata فایل و افزودن عکس به گالری همان پروژه.
7. ثبت دستی حافظهٔ همان پروژه با منشأ، تاریخ، نسخه، ویرایش، حذف و ترجیح استفاده در زمینه.
8. جست‌وجوی محلی در حافظه و شناسنامهٔ فایل‌های پروژهٔ فعال و بازکردن رکورد اصلی.
9. Build برای تعریف، پیش‌نمایش و فعال‌سازی محلی یک نمای امن و فقط‌خواندنی همان پروژه.
10. Brief روزانه یا هفتگی از منوی سمت راست.

برای تست خطا می‌توان از `CHD-0000` یا OTP برابر `000000` استفاده کرد.

## اجرا

```bash
npm ci --prefer-offline --no-audit --no-fund
npm run dev
```

## کنترل کیفیت

```bash
npm run test:app -- --grep "نام regression مرتبط"
npm run check:runtime
npm run build
```

این مسیر توسعهٔ متمرکز است: فقط regression مرتبط، integrity runtime و یک build پس از جمع‌شدن همان بستهٔ بازخورد. `gate:release` گیت نهایی یک‌باره است و فقط روی candidate منجمدِ انتشار صریح یا پایان برش پرریسک معماری اجرا می‌شود؛ build/integrity/TypeScript، همهٔ Playwright، Sites و whitespace را اجرا و fingerprint دقیق source و `dist` را در `.git` ثبت می‌کند. `test:runtime` فقط هشت تست runtime را اجرا می‌کند. انتشار بعدی فقط از همان candidate دست‌نخورده، پس از commit و موفقیت `gate:publish` انجام می‌شود.

فایل‌های app-specific فقط در `src/Prototype.tsx` و `src/prototype.css` قرار دارند. runtime تست موبایل از template رسمی Product Design حفظ شده، اما chrome نمایشی آن در مسیر واقعی اپ پنهان است. در candidate محلی و هنوز منتشرنشدهٔ BG-F1، Project و ProjectProfile در envelope نسخهٔ ۳ با Identity/Policy fixture دقیق، active project اتمیک، migration fail-close و writer چندتب نگه‌داری می‌شوند؛ کلیدهای v2/legacy فقط ورودی cutover هستند. Build یک `BuiltArtifact` declarative و project-scoped از کاتالوگ بسته است و هیچ پلاگین/اسکیل واقعی، کد آزاد یا نصب خارجی نمی‌سازد. Brief، چت، شناسنامهٔ پروژه، metadata اسناد، حافظهٔ دستی و بازیابی در این مرحله فقط داخل مرورگر شبیه‌سازی می‌شوند؛ Blob عکس و سند انتخاب‌شده در IndexedDB همان مرورگر می‌ماند و هیچ محتوایی آپلود یا همگام‌سازی نمی‌شود. تاریخچهٔ چت حافظه نیست و ترجیح استفادهٔ یک حافظه هنوز به مدل متصل نمی‌شود. جست‌وجوی فعلی فقط روی حافظهٔ دستی و شناسنامهٔ فایل‌های پروژهٔ فعال است؛ محتوای فایل، OCR، وب، بازار، پاسخ AI و citation تا اتصال منابع واقعی غیرفعال‌اند. اگر خواندن فایل‌ها یا حافظهٔ محلی کامل نشود، آن وضعیت empty تلقی نمی‌شود و ثبت/ویرایش همان مخزن تا یک بارگذاری موفق بعدی مسدود می‌ماند.
